## 1. การโจมตีตามเวลา

**เห็นอะไร**
- มี 2 รอบเก็บข้อมูล การโจมตีอยู่ในรอบ 1: 14%, 2: 86%
- ไม่มีการโจมตีเลยช่วง 01:00–10:59 (มีแต่ทราฟฟิกปกติ)
- ชั่วโมงที่แต่ละประเภทเกิดมากสุด: Generic 16:00, Exploits 23:00, Fuzzers 23:00, DoS 23:00, Reconnaissance 22:00, Analysis 23:00, Backdoor 23:00, Shellcode 23:00, Worms 22:00
- ช่วงการโจมตี (campaign) ยาวเฉลี่ย (median): Generic 63 นาที, Exploits 63 นาที, Fuzzers 61 นาที, DoS 63 นาที, Reconnaissance 63 นาที, Analysis 12 นาที, Backdoor 104 นาที, Shellcode 115 นาที, Worms 12 นาที
- หลัง Reconnaissance ประเภทที่เริ่มต่อบ่อยสุดคือ Exploits (50%) (หลายประเภทรันพร้อมกัน ใช้ดูแนวโน้มเท่านั้น)
- สัดส่วนการโจมตีในแต่ละรอบ: รอบ 1 1.4%, รอบ 2 8.2% แต่สัดส่วนประเภทภายในการโจมตีต่างกันไม่เกิน 7.1 จุด %

**ตัดสินใจ / เข้าใจอะไร**
- drift อยู่ที่ 'ปริมาณการโจมตี' ไม่ใช่ 'ประเภท' -> โมเดลที่เรียนจากรอบหนึ่งจะเจออัตราการโจมตีต่างไปในอีกรอบ (หลักฐาน H2)
- ต้องแบ่ง train / val / test ตามเวลา และเช็กว่าทุกชุดมีครบ 10 คลาส
- Analysis / Worms มาเป็นช่วงสั้นๆ หลายครั้ง ส่วนประเภทอื่นรันยาวต่อเนื่อง ~1 ชม. พร้อมกัน
- ข้อจำกัด: มีแค่ 2 รอบ และการโจมตีถูกปล่อยด้วยเครื่องมือในแล็บ ชั่วโมงที่เกิดจึงสะท้อนตารางการทดลอง ไม่ใช่พฤติกรรมแฮกเกอร์จริง

**เห็นอะไร**

- การโจมตีไปที่: AU 100.0%
- KP ยังมีทราฟฟิกปกติ 38,390 แถว
- เครื่องผู้โจมตี 4 เครื่องทำครบทุกประเภท ส่วนใหญ่สัดส่วนใกล้กัน ยกเว้น 175.45.176.2 ทำ Generic แค่ 7% แต่เน้น Exploits 36% แทน -> แทบไม่ได้แบ่งหน้าที่ตามเครื่อง
- ทราฟฟิกปกติของ KP หน้าตาใกล้การโจมตี (median sbytes / dbytes / spkts / sttl ใกล้กัน ดู eda_*_kp_normal_vs_attack.csv)

**ตัดสินใจ / เข้าใจอะไร**
- ประเทศบอกได้ว่า 'โจมตีหรือไม่' ทันที (ถ้าไม่ใช่ KP = ปกติ) แต่แยก 'ประเภท' ไม่ได้ เพราะทุกประเภทมาจาก KP เหมือนกัน -> H1 คาดว่าใส่ประเทศแล้วช่วยแยกโจมตี/ปกติ แต่ไม่ช่วยแยกประเภท
- ประเทศสะท้อนบทบาทในแล็บ ไม่ใช่ตำแหน่งผู้โจมตีจริง -> โมเดลหลักไม่ใช้ geo
- srcip ต้องอยู่ใน drop (ถ้าใส่ โมเดลจะจำ IP แทนการเรียนพฤติกรรม)

## 4. โปรไฟล์เครือข่ายต้นทาง

**เห็นอะไร**
- มีเครือข่ายต้นทาง 5 กลุ่ม การโจมตีมาจาก 1 เครือข่าย: STAR-KP (Star Joint Venture Co. Ltd., ISP) โจมตี 72.2% ของที่ส่ง
- ทราฟฟิกปกติส่วนใหญ่มาจาก: JTCL-JP-AS (ISP) 1,887,832 แถว, UNSW-AS-AP (Business) 23,170 แถว
- อัตราการโจมตีตามประเภทเครือข่าย: Business 0.0%, ISP 4.9%, private/loopback 0.0%

**ตัดสินใจ / เข้าใจอะไร**
- ASN ให้ข้อมูลซ้ำกับประเทศ 100% (1 ประเทศ = 1 เครือข่ายใน UNSW) -> ไม่ต้องใส่ทั้ง country และ asn ในโมเดลทดลอง H1
- ประเภทเครือข่าย (ISP / Business) อธิบายบทบาทในแล็บได้: ผู้ใช้ปกติและผู้โจมตีถูกจำลองเป็น ISP ส่วนเซิร์ฟเวอร์เป็นมหาวิทยาลัย
- ถ้าใช้ข้อมูลจริงที่มีหลายเครือข่าย ASN / ASNType จะเป็น feature ที่น่าสนใจกว่านี้ (ข้อเสนอแนะในรายงาน)

## 5. คลาสไม่สมดุล + เพดานคะแนน

**เห็นอะไร**
- Normal 95.2% ของข้อมูล คลาสเล็กสุด Worms 171 แถว (ห่างกัน 11,461 เท่า)
- ทาย Normal ทุกแถวก็ได้ accuracy 95.2%
- เพดาน Macro F1 (แม้จำข้อมูลได้หมด) = 0.795 คลาสที่เพดานต่ำ: Backdoor 0.30, Analysis 0.33, DoS 0.77

**ตัดสินใจ / เข้าใจอะไร**
- ใช้ Macro F1 เป็น metric หลัก ไม่ใช้ accuracy
- ใช้ class_weight='balanced' ทุกโมเดล
- ตั้งความคาดหวัง: Macro F1 บน test จะต่ำกว่า 0.80 แน่นอน

## 6. ทางลัด (leakage)

**เห็นอะไร**
- ใช้คอลัมน์เดียวทายได้ดีสุด: sbytes 0.39, smeansz 0.34, dbytes 0.31, dmeansz 0.26, sload 0.24
- Macro F1 (ตัวอย่างสุ่ม คลาสละ ≤ 20,000): all base 0.62, base + check 0.65, check only (TTL) 0.24, geo only 0.13
- ใช้แค่ TTL 3 คอลัมน์ได้ 38% ของคะแนน base ทั้งหมด
- sttl ที่พบบ่อยสุดตามประเทศต้นทาง: AU 60 (87%), JP 31 (100%), KP 254 (80%)

**ตัดสินใจ / เข้าใจอะไร**
- sttl เป็น 'ลายนิ้วมือของเครื่องต้นทาง' (แต่ละประเทศ/เครื่องมีค่าประจำตัว) ทำหน้าที่เหมือน src_country -> ช่วยแยกโจมตี/ปกติได้ทันที แต่แยกประเภทได้น้อย เพราะการโจมตีทุกประเภทมาจากเครื่องชุดเดียวกัน
- เพิ่ม TTL เข้า base ทำให้คะแนนขึ้นแค่ 0.03 -> เสนอทีมตัด TTL ไปไว้ใน drop (หรือทดสอบคู่กับ H1 แบบมี/ไม่มี) ใน Progress 4
- geo ใช้แยกประเภทได้น้อย (สอดคล้องกับหัวข้อ 2 และ 4) -> ทดสอบใน H1
- คะแนนนี้มาจากตัวอย่างแบ่งแบบสุ่ม ใช้จัดอันดับเท่านั้น ไม่ใช่คะแนนโมเดลจริง

## 7. คุณภาพข้อมูล

**เห็นอะไร**
- ค่าว่างก่อน clean อยู่แค่ 4 คอลัมน์ หลัง clean เหลือเฉพาะ port (11 ช่อง) ซึ่งไม่เข้าโมเดล
- ลบแถวซ้ำไป 480,633 แถว
- แถวที่ feature เหมือนกันทุกตัว: แบ่งแบบสุ่ม test 2.7% มีแถวหน้าตาเดียวกันอยู่ใน train ส่วนแบ่งตามเวลาเหลือ 2.4%
- คลาสที่ข้อมูลทับกับคลาสอื่นมากสุด: Backdoor 82%, Analysis 80%, DoS 36%

**ตัดสินใจ / เข้าใจอะไร**
- ข้อมูลพร้อมใช้ ไม่ต้อง clean เพิ่ม
- แบ่งสุ่มกับแบ่งตามเวลารั่วพอๆ กัน (ต่างกัน 0.3 จุด %) -> แถวซ้ำไม่ใช่เหตุผลหลักของ H3 เหตุผลที่ต้องแบ่งตามเวลามาจาก drift (หัวข้อ 1) แทน
- Backdoor / Analysis จะได้ F1 ต่ำไม่ว่าใช้โมเดลไหน -> เขียนเป็นข้อจำกัด
