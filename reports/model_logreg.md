ในการทดลองรอบ Progress 4 นี้ ได้นำข้อค้นพบเชิงลึกจากการสำรวจข้อมูล (EDA ใน Progress 3) มาออกแบบการทดลองโมเดล **Logistic Regression** อย่างเป็นระบบ เพื่อตอบโจทย์ 3 มิติหลัก:

1. **ได้คะแนน Macro F1 สูงที่สุด (0.3836):**
   การใช้ `n_normal = 800,000` ทำคะแนน Macro F1 ได้สูงกว่าการใช้ข้อมูล Normal เต็มจำนวน 1.39 ล้านแถว (0.3833) เล็กน้อย แสดงให้เห็นว่าทราฟฟิกปกติส่วนเกินมีลักษณะซ้ำซ้อน (Redundant Rows) การตัดออกบางส่วนช่วยลด Bias ที่จะกดทับ Minority Attack Classes
2. **รักษา Recall สูงสุด (0.6171):**
   อัตราการตรวจจับการโจมตีไม่ลดลงเลยแม้แต่น้อย โดยได้ Recall เท่ากับ Full Dataset (0.6171) และสูงกว่าระดับ 50,000 ถึง 400,000
3. **ลดระยะเวลาการคำนวณลง 50%:**

4. **รักษาความหลากหลายของพฤติกรรมปกติ (Normal Diversity):**
   ขนาด 800,000 แถวคิดเป็นกว่า 57.5% ของทราฟฟิกปกติทั้งหมดใน Train Set ซึ่งครอบคลุมทุก Protocol, Service, และช่วงเวลา ต่างจากการลดลงไปถึง 50,000 ที่อาจทำให้โมเดลขาดตัวอย่าง Normal บางประเภทจนเกิด False Positive สูงขึ้นในโลกจริง

### 2.2 การวิเคราะห์เชิงลึก:

#### ก) ผลของ `class_weight='balanced'` vs `None` (Precision-Recall Trade-off):
- **เมื่อใช้ `class_weight='balanced'`:**
  โมเดลคูณค่าน้ำหนักโทษผกผันกับความถี่ของคลาส ทำให้เมื่อโมเดลทายการโจมตีขนาดเล็กผิด (เช่น Worms ที่มีเพียง 171 ตัวอย่าง หรือ Backdoor) Loss จะสูงมาก บังคับให้ Sigmoid Decision Boundary ขยับเข้าหาพื้นที่ของ Normal ส่งผลให้ **Recall พุ่งขึ้นจาก 0.3666 เป็น 0.6255 (+70.6%)** และรักษา Macro F1 ให้อยู่ในระดับสูง (0.3795) ซึ่งเป็นคุณสมบัติที่ระบบตรวจจับการบุกรุก (NIDS) ต้องการสูงสุด
- **เมื่อปรับเป็น `class_weight=None`:**
  Loss Function ให้ความสำคัญกับคลาส Normal 95.16% เท่าเทียมกับคลาสอื่น โมเดลจึงเลือกทายว่า "Normal" แทบทั้งหมด ส่งผลให้ **Recall ดิ่งลงเหลือเพียง 0.3666** (ปล่อยการโจมตีหลุดไปถึง 63.34%) 
  อย่างไรก็ดี **PR-AUC กลับเพิ่มขึ้นเป็น 0.4015** เพราะ Probability Output ของโมเดลถูก Calibrate ตามสัดส่วนประชากรจริง (Unbiased Prior) ไม่ถูกบิดเบือนด้วยตัวคูณน้ำหนักโทษ
- **การเพิ่ม Log Transformation (`np.log1p`):**
  การใส่ `np.log1p()` บนฟีเจอร์ปริมาณที่มีค่าความเบ้สูงมาก (`sload`, `sbytes`, `dur`, ฯลฯ) ช่วยดึง Outliers มหาศาลกลับเข้ามา ทำให้ Decision Boundary มีความ Smooth ขึ้น ส่งผลให้ **Recall ขยับขึ้นสู่จุดสูงสุดที่ 0.6255 บน Validation Set**

#### ข) ผลของการเพิ่มฟีเจอร์ Geolocation (`+ Geo` 42 คอลัมน์):
- เมื่อเพิ่ม `src_country`, `dst_country`, `src_asn`, `dst_asn` เข้าไปใน Base Model ส่งผลให้คะแนนพุ่งขึ้นอย่างก้าวกระโดด:
  - **Macro F1:** เพิ่มขึ้นจาก 0.3795 $\rightarrow$ **0.4141 (+0.0346)**
  - **PR-AUC:** เพิ่มขึ้นจาก 0.3244 $\rightarrow$ **0.4118 (+0.0874)**
- **คำอธิบายทางสถิติ:** นี่คือหลักฐานชัดเจนของ **Shortcut Learning (Spurious Correlation)** ตามที่ระบุไว้ใน EDA ข้อ 3 เนื่องจากการโจมตีทุกคลาสใน UNSW-NB15 ถูกปล่อยมาจากบล็อก IP `175.45.176.0/24` ซึ่งถูกจับคู่เข้ากับประเทศ `KP` และ ASN `131279` โมเดล Linear Classifier จึงเรียนรู้น้ำหนักเชิงบวกขนาดใหญ่ให้กับ Dummy Variable `src_country_KP` เพื่อใช้เป็น "ทางลัด" ในการแยกแยะทราฟฟิกโจมตีออกจาก Normal โดยไม่ต้องพิจารณาพฤติกรรมโฟลว์จริง

### 3.2 การวิเคราะห์เชิงลึก:

#### ก) ผลกระทบของ Data Leakage จากฟีเจอร์ TTL:
- การนำฟีเจอร์กลุ่ม TTL เข้าสู่โมเดล ส่งผลให้เกิดการก้าวกระโดดของคะแนนอย่างมหาศาลเมื่อเทียบกับ Base Model:
  - **Macro F1:** กระโดดขึ้นจาก 0.3795 $\rightarrow$ **0.4247 (+0.0452)**
  - **PR-AUC:** กระโดดขึ้นจาก 0.3244 $\rightarrow$ **0.4197 (+0.0953)**
- **สาเหตุเชิงประจักษ์:** เกิดจาก **Testbed Configuration Artifact** ในห้องแล็บ UNSW ที่เครื่องปล่อยการโจมตี (Attack Source) ตั้งค่าเริ่มต้นของ Time-to-Live ไว้ที่ `sttl = 254` (Standard Deviation = 0.00 สำหรับบางคลาส เช่น Shellcode) ขณะที่ทราฟฟิกปกติจากอินเทอร์เน็ตจริงมีค่าเฉลี่ย `sttl = 31` ทำให้ค่าสัมประสิทธิ์ของ `sttl` กลายเป็นตัวแยกแยะที่ทรงพลังเกินจริง

#### ข) ผลเมื่อรวมทั้ง TTL และ Geo เข้าด้วยกัน (`With TTL + Geo` รวม 45 คอลัมน์):
- โมเดลที่ใส่ทั้ง TTL และ Geolocation สามารถทำคะแนนได้สูงที่สุดในทุกการทดลอง โดยแตะ **Val Macro F1 = 0.4287** และ **Test Macro F1 = 0.4221**
- **แต่ข้อสังเกตสำคัญเชิงทฤษฎีคือ:**
  - เมื่อโมเดลมี TTL อยู่แล้ว (F1 = 0.4247) การเพิ่ม Geo เข้าไปอีก ช่วยให้คะแนนขยับขึ้นเพียง **+0.0040** เท่านั้น
  - ในทำนองเดียวกัน เมื่อโมเดลมี Geo อยู่แล้ว (F1 = 0.4141) การเพิ่ม TTL เข้าไป ช่วยให้คะแนนขยับขึ้น **+0.0146**
  - ตัวเลขนี้สะท้อนว่า **TTL Leakage และ Geo Shortcut ให้ข้อมูลที่ซ้ำซ้อนกันอย่างมาก (High Information Redundancy)** เนื่องจากเครื่องคอมพิวเตอร์ในห้องแล็บที่ปล่อยค่า `sttl=254` ก็คือเครื่องเดียวกันกับที่ถือ IP บล็อก `175.45.176.0/24` (ประเทศ KP) นั่นเอง ทั้งสองฟีเจอร์จึงเป็นภาพสะท้อนของแหล่งกำเนิดเดียวกัน

1. **เพดานประสิทธิภาพทางทฤษฎี (Theoretical Ceiling & Bayes Error Rate):**
   - แม้จะปรับโมเดลจนดีที่สุด Macro F1 ของ Base Model ยังคงอยู่ที่ประมาณ **0.3757 - 0.3836** 
   - เหตุผลไม่ได้เกิดจากจุดอ่อนของ Logistic Regression เพียงอย่างเดียว แต่เกิดจาก **Label Conflicts รุนแรงในดาต้าเซ็ต** (ตามรายงาน EDA ข้อ 4) ที่พบว่าคลาส `Backdoor` มีฟีเจอร์ซ้ำซ้อนกับคลาสอื่นถึง **82.5%** และ `Analysis` ซ้ำซ้อน **79.8%** เมื่อตัด IP และเวลาออก ข้อมูลของสองคลาสนี้แทบไม่มีความแตกต่างทางสถิติจากทราฟฟิกปกติ ทำให้โมเดลเชิงเส้นไม่สามารถลาก Hyperplane แบ่งแยกได้อย่างสมบูรณ์
2. **บทบาทของ Log Transformation (`np.log1p`):**
   - การทำ Log Transform บนตัวแปรกลุ่ม Heavy-Tailed ช่วยกำจัดปัญหา Outliers ที่ค่ากระโดดไปถึงระดับพันล้าน ทำให้โมเดลลู่เข้า (Convergence) เร็วขึ้น และเพิ่มเสถียรภาพของค่าสัมประสิทธิ์ฟีเจอร์
3. **การรักษาความสมดุลของ Cost-Sensitive Weighting:**
   - การเลือกใช้ `class_weight="balanced"` มีความสำคัญอย่างยิ่งยวดสำหรับงาน Cyber Threat Detection เนื่องจากช่วยรักษาระดับ Recall ไว้ได้สูงกว่า 60% ซึ่งป้องกันการเล็ดลอดของผู้ไม่ประสงค์ดีเข้าสู่ระบบ

### 4.3 ข้อเสนอแนะเชิงสถาปัตยกรรมและการนำไปใช้งานจริง (Operational Recommendations):

> [!IMPORTANT]
> **โมเดลที่ต้องนำไปใช้งานจริงในระบบ Production คือ "Base Model (Without TTL, Without Geo)" เท่านั้น**

- **เหตุผล:**
  1. **ห้ามพึ่งพา TTL ในระบบตรวจจับภายนอก:** ในเครือข่ายจริง ค่า TTL ของทราฟฟิกโจมตีจะถูกปรับเปลี่ยน (Hop Count Decoupling / NAT / Firewall Packet Mangling) ทำให้ค่า `sttl` ไม่ได้คงที่อยู่ที่ 254 หากนำโมเดล With TTL ไปใช้ โมเดลจะตรวจจับการโจมตีจริงแทบไม่ติด (Catastrophic False Negatives)
  2. **ห้ามพึ่งพา Geolocation เป็นตัวตัดสินหลัก:** การโจมตีในโลกความเป็นจริงสามารถมาจากพร็อกซีหรือเซิร์ฟเวอร์ในประเทศใดก็ได้ทั่วโลก หากโมเดลจำทางลัดว่า `src_country == 'KP'` คือโจมตี แฮกเกอร์ที่ยิงมาจากเซิร์ฟเวอร์ในสหรัฐฯ หรือญี่ปุ่นจะสามารถผ่านระบบตรวจจับได้ 100% (Spurious Shortcut Bypass)
  3. **คะแนน 0.3757 ของ Base Model คือคะแนนที่สะท้อน "พฤติกรรมการไหลของข้อมูล (Behavioral Traffic Features)" อย่างแท้จริง** ซึ่งมีความคงทน (Robustness) ต่อการย้ายไปติดตั้งบนสภาพแวดล้อมเครือข่ายใหม่มากที่สุด
